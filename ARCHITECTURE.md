# Rivet Agents — Architecture

Python agent service for Rivet. Runs on Render. The Rivet UI and any other channel (MCP, CLI) POST to this service.

## Cascade

```
app.py (FastAPI router)
  └── Agent (agents/*.py)           — id, model, skill list, tool list
        └── Skill (skills/<name>/)  — SKILL.md + resources/
              └── resources/*.md    — ALL logic and rules (Markdown, not code)
        └── Tools (tools/*.py)      — thin callables + Anthropic schemas
              └── runtime/loop.py   — single place for all Anthropic API calls
              └── db/supabase_client.py — Supabase reads/writes
```

## Design rule

**Code is plumbing. Logic lives in `.md` files.**

Skills are Markdown, not Python. All agent behavior, decision rules, output formats, and guidance live in `SKILL.md` and `resources/*.md`. Adding a new capability means writing a `.md` file, not editing the runtime.

## Endpoints

| Endpoint | Purpose |
|----------|---------|
| `POST /agent` | Structured single-pass tasks (`refresh-scope`, `price-materials`) |
| `POST /chat` | Conversational SSE stream — contractor advisor agent |
| `GET /conversation/{id}` | Load saved conversation for page-load resumption |
| `GET /health` | Health check |

## Multi-model

| Model | When | Pattern |
|-------|------|---------|
| Haiku | Single-pass focused tasks | All skill content pre-injected into system prompt, one API call |
| Sonnet | Tool-use loops, conversational agents | Loop: stream tokens → execute tools → stream next turn |

## Agents

### job-advisor (Haiku)
Analyzes a single work item and returns whether it is ready to quote or needs clarifying questions. Called by `refresh-scope` task. Output: `{ readyToQuote, questions[], context }`.

### material-pricer (Sonnet)
Generates a Bill of Materials with live price ranges using Exa AI web search. Called by `price-materials` task. Output: BOM JSON with `materials[]`, `total_low/mid/high`, `region`.

### contractor-advisor (Sonnet)
Conversational agent accessible via `POST /chat` (SSE streaming). Helps contractors manage their full pipeline through natural language. Can perform every action available in the UI.

**Tools available to contractor-advisor:**

| Tool | File | Action |
|------|------|--------|
| `list_work_items` | `tools/work_items.py` | Query pipeline by status |
| `get_work_item_detail` | `tools/work_items.py` | Full detail on a single job |
| `refresh_scope` | `tools/agent_tasks.py` | Run job-advisor, update scope_analysis |
| `price_materials` | `tools/agent_tasks.py` | Run material-pricer, update BOM |
| `re_estimate_job` | `tools/agent_tasks.py` | Call re-estimate Netlify fn, refresh price/rec |
| `send_estimate` | `tools/contractor_actions.py` | Mark quoted + email customer |
| `email_client` | `tools/contractor_actions.py` | Free-form email to customer via Resend |
| `accept_work` | `tools/contractor_actions.py` | Set opStatus to approved |
| `reject_work` | `tools/contractor_actions.py` | Set opStatus to declined |
| `update_work_price` | `tools/contractor_actions.py` | Write new price + optional reason_code |
| `add_contractor_note` | `tools/contractor_actions.py` | Append note to work item |

## SSE stream format (`POST /chat`)

```
event: text    data: <token>              — streaming response text
event: tool    data: <label>             — tool being called (UI shows thinking label)
event: chips   data: ["chip1","chip2"]   — contextual follow-up suggestions
event: id      data: <conversation_uuid> — persist to localStorage
event: done    data:                     — stream complete
```

Chips are generated by the agent inside `<chips>[...]</chips>` blocks in its response text. The runtime strips them from visible text and emits them as a separate event.

## Chip system

The contractor-advisor skill instructs the agent to end every response with:
```
<chips>["Send the Acme Corp estimate", "What else needs attention?"]</chips>
```

The UI renders chips as pill buttons below each assistant message. Clicking a chip sends it as the next user message — contractors rarely need to type. Initial chips shown on empty conversation:
- "What should I work on this week?"
- "Any estimates I need to send?"
- "Are there jobs waiting on customer info?"
- "Show me what's approved and ready to schedule"

## Conversation persistence

Conversations saved to `contractor_conversations` Supabase table. `conversationId` returned as `event: id` and stored in browser `localStorage`. On page load, `GET /conversation/{id}` restores history.

**Migration required (run once in Supabase SQL editor):**
```sql
create table contractor_conversations (
  id uuid primary key default gen_random_uuid(),
  business_id text not null,
  messages jsonb not null default '[]',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
create index on contractor_conversations(business_id);
```

## File structure

```
agents/
  job_advisor.py              — Job Advisor (Haiku, single-pass)
  material_pricer.py          — Material Pricer (Sonnet, Exa tool-use)
  contractor_advisor.py       — Contractor Advisor (Sonnet, 11 tools, /chat)

skills/
  scope-clarifier/
    SKILL.md                  — scope analysis instructions
    resources/
      question-patterns.md   — per-trade question logic
  material-pricer/
    SKILL.md                  — BOM generation + Exa search guidance
  contractor-advisor/
    SKILL.md                  — conversational guidance, chips rule, action protocol
    resources/
      workflow-stages.md      — opStatus meanings and next actions
      priority-signals.md     — how to rank what to work on

tools/
  exa_search.py               — Exa AI web search (material pricing)
  work_items.py               — Supabase reads: list + detail
  contractor_actions.py       — mutations: send estimate, email, accept, reject, price, note
  agent_tasks.py              — invoke other agents: refresh_scope, price_materials, re_estimate_job

runtime/
  loop.py                     — Anthropic API calls (Haiku, Sonnet, streaming)
  registry.py                 — agent/skill registration and content loading

db/
  supabase_client.py          — Supabase service client (work items, conversations)

app.py                        — FastAPI entry point, task router, /chat SSE endpoint
```

## Adding a new agent

1. Create `skills/<skill-name>/SKILL.md` — write all logic here, not in code
2. Add resource files in `skills/<skill-name>/resources/` as needed
3. Create `tools/<name>.py` with callable + Anthropic tool schema (if tools needed)
4. Create `agents/<name>.py`, call `register_agent()`
5. Register tool executors in `runtime/loop.py` `TOOL_EXECUTORS` dict
6. For structured tasks: add a task case in `app.py`; for conversational: use `POST /chat`

## Environment variables

| Variable | Required | Description |
|----------|----------|-------------|
| `ANTHROPIC_API_KEY` | Yes | Anthropic API key |
| `SUPABASE_URL` | Yes | Supabase project URL |
| `SUPABASE_SERVICE_KEY` | Yes | Supabase service role key |
| `EXA_API_KEY` | Yes | Exa AI search (material pricing) |
| `RESEND_API_KEY` | Yes | Email sending (send_estimate, email_client tools) |
| `RESEND_FROM_EMAIL` | Yes | Sender address for outbound emails |
| `SITE_URL` | Yes | Base URL for quote links in estimate emails |
| `NETLIFY_URL` | Yes | Rivet Netlify deploy URL (re_estimate_job tool calls back to it) |
| `PORT` | No | Server port (default 8000) |
